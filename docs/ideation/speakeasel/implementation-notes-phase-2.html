Implementation Notes — Phase 2

speakeasel · 2026-09-02 · The Editor: Fabric-free scene store + thin Fabric renderer + toolbar/object-list UI

Scene store — exportRequests added to SceneState, excluded from history

Context
The spec's store API says requestExport() "bumps exportRequests counter; renderer downloads", but the SceneState interface sketch omits the field (flagged in the context map as a known gap).
Decision
Added exportRequests: number to state; the renderer diffs it against a lastExportCount and downloads on increase. Snapshots deliberately exclude it and restore() carries the live value forward — exporting is not undoable, and undo must never re-trigger a download.
Alternative
An out-of-band event/callback channel from scene to renderer — rejected: it would be the store's only non-state signal and break the "renderer is a pure projection of state" pattern.

Scene store — endGesture() added to close drag coalescing

Context
The spec requires {fromRenderer: true} moves to coalesce into one history entry per drag-release, but gives no mechanism to separate two consecutive drags of the same object (both would carry the same coalesce identity).
Decision
Additive scene.endGesture(): fromRenderer moves coalesce under a move:{id} key; the renderer calls endGesture() on Fabric's object:modified (release), so the next drag pushes a fresh snapshot. The frozen mutator contract is unchanged — this is a new method, not a rename.
Alternative
Only syncing on object:modified (one call per drag, no coalescing needed) — rejected: the object list would not update live mid-drag, weakening the "mirrors both directions" manual criterion.

Scene store — loadImage resets adjustments/rotation/crop, keeps captions

Context
The spec is silent on what happens to existing edits when a new image loads.
Decision
A new photo starts fresh (adjustments 0, rotation 0, crop null) — the old photo's crop rect has no meaning on a different image. Captions survive: they are percent-positioned and belong to the composition, not the photo. Undo restores the previous image together with its edits (one snapshot).
Alternative
Carrying all edit state across loads — rejected: a stale crop/rotation silently mangles the new photo, the "wrong region cropped" failure mode by another route.

Scene store — rotate(degrees) sets absolute rotation

Context
rotate(degrees) // normalize into 0..359 is ambiguous between relative ("rotate by") and absolute ("rotate to"). State holds a single normalized rotation field.
Decision
Absolute set, matching every other mutator (setAdjustment, cropRect) and giving agents an idempotent, predictable call. The toolbar's "Rotate 90°" button computes (current + 90) % 360 itself.
Alternative
Relative rotation — rejected: non-idempotent for agents (retries double-rotate) and Phase 3 can trivially build relative on top of absolute, not vice versa.

Boot — sample auto-loads through loadSample()

Context
Spec Data Model: default state has no image ("sample loadable"). Phase 1's boot drew the sample scene directly so the easel is never blank, and the live demo URL depends on visible content.
Decision
createInitialState() keeps image: null per spec; main.ts calls scene.loadSample() at boot — the same one-code-path route as uploads. Cost: canUndo is true immediately (undo returns to a blank easel), which is honest history.
Alternative
Booting blank — rejected: regresses the deployed demo from Phase 1's never-blank easel. The sample source is injected via registerSampleSource() so the scene layer stays Fabric-free and Node-testable.

Renderer — display-space projection; oversize uploads re-encode as JPEG

Context
Spec suggests "crop maps to the canvas viewport"; it also mandates downscaling >4096px images to ≤2048px "for canvas perf + dataURL size" without naming a format. Text size units are unspecified.
Decision
Kept the viewport identity and computed layout in display space instead: canvas dimensions take the visible (crop) region's aspect, the image object is scaled/offset so the crop fills the canvas, rotation spins the image around its center under the canvas-aligned window (crop math stays in unrotated image space, per the Failure Modes table). Texts live at percent-of-canvas with fontSize in display px; export uses toDataURL({ multiplier: 1/dispScale }) to restore natural resolution. Downscaled oversize images re-encode as JPEG at 0.92 — a 2048px PNG dataURL of a photo would defeat the size motivation.
Alternative
Viewport-transform cropping with objects in image space — rejected: text font sizes would need image-relative scaling and the no-image case (texts on a blank 800×600 easel) would need a second coordinate system.

Toolbar — adjustment sliders commit on change, not input

Context
The spec says every mutator pushes a history snapshot, with fromRenderer drags as the only coalesced exception. A slider drag fires dozens of input events.
Decision
Sliders call scene.setAdjustment on change (release): one history entry per gesture, keeping the 50-entry cap meaningful. The spec's experiment ("adjust brightness slider → visible change") still holds.
Alternative
Live preview via input events — rejected: floods history per the spec's own push rule; extending coalescing to adjustments would silently widen the spec's single stated exception.
