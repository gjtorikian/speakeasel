A11y pass — three files the spec's File Changes table omits

Context
The spec's Implementation Details require the aria-live feed to announce "summary line only, not args JSON", and the canvas aria-label to be "kept in sync from the same summarizer" — but the File Changes table lists neither src/ui/activity.ts (where the live region lives), nor src/webmcp/tools.ts (where summarize() was module-private), nor src/main.ts (the only place to wire the subscription).
Decision
Modified all three, per the scout's context-map risk entry: activity.ts renders entry.summary as announced text with the ✓/✗ glyph, args JSON, and timestamp aria-hidden; tools.ts exports summarize; main.ts subscribes after renderer.init and re-sets the label on every scene change, and also sets aria-hidden on Fabric's pointer-only .upper-canvas.
Alternative
Satisfying the aria-label from index.html alone — rejected: static HTML cannot track state (the map flags this explicitly).

Toolbar — natural tab order instead of roving focus; focus rescue on disable

Context
The spec says "roving focus where apt". Three toolbar children are input[type=range] whose arrow keys must keep adjusting values, so APG toolbar arrow-key navigation conflicts with the controls themselves.
Decision
Kept natural tab order (documented honestly in the README a11y statement). Added one real keyboard fix: when undo/redo becomes disabled while focused, focus is handed to a live neighbor instead of silently dropping to <body>. Object-list rows are focusable (tabindex=0, data-id) with focus restoration across the wholesale replaceChildren re-render (same id → numeric successor → heading).
Alternative
Roving tabindex between toolbar groups — rejected as over-engineering that risks a real trap for a claimed win; the spec's decision log frames chrome operability, not APG maximalism, as the bar.

Ship mechanics — deploy and gh repo create deferred to the post-review stage

Context
The spec's "Final ship" section runs ./scripts/deploy.sh and gh repo create speakeasel --public --source . --push. This build stage runs under engine overrides: stop after Verify, do not commit — a sibling reviewer reviews the diff and a later stage commits.
Decision
Deferred both. Deploying would publish unreviewed, uncommitted working-tree code to prod, and gh repo create --push would publish a repo whose Phase 4 deliverables (README, LICENSE, SUBMISSION.md, og.png) exist only as uncommitted files — contradicting both the review gate and the spec's own "filmed build ≠ deployed build" mitigation (deploy must follow the final code state). All five contract validation commands pass without them: the live-URL curl check is green against the current Phase 3 deployment. The exact remaining commands are in the context map's "Phase 4 Validation" section: ./scripts/deploy.sh, then gh repo view gjtorikian/speakeasel || gh repo create speakeasel --public --source . --push (after the phase commit, which should include docs/ideation/ per the loopmate precedent).
Alternative
Shipping from this stage — rejected: irreversible public side effects from a pre-review working tree.
